# Slide Archetypes

Choose one visual argument per slide. Do not use a complex diagram when a strong statement is clearer.

| Investor job | Recommended archetype | Visual grammar |
|---|---|---|
| Category claim | Category bridge | Fragmented alternatives flow into a named layer and outcomes |
| Problem | Bottleneck flow | Inputs converge on manual work, risk, or delay |
| Why now | Timeline or forcing-function stack | Regulation, technology, and buyer urgency converge |
| Solution | Three-part system | Distinct capabilities connect through one platform |
| Product | Annotated product view | Real interface or workflow with restrained callouts |
| Traction | Evidence hierarchy | One dominant proof metric plus supporting customer evidence |
| Market | Nested market map | Narrow wedge expands into adjacent spend pools |
| Business model | Value exchange | Buyer, price unit, gross margin, and expansion path |
| Competition | Positioning map or alternative table | Competitive alternatives and the attribute that changes the decision |
| Moat | Reinforcing loop | Data, workflow adoption, distribution, and credibility compound |
| Go-to-market | Land-and-expand flow | Entry buyer, trigger, deployment, expansion, and channel |
| Team | Capability-to-milestone map | Why this team can unlock the next stage |
| Ask | Capital-to-milestone path | Funding maps to specific milestones and measurable outcomes |
| Human workflow | Buyer-to-outcome scene | Real operators and users make the workflow, pain, and value tangible |
| Physical transformation | Material input-to-output | Documents, evidence, products, or operational artifacts visibly change state |
| Environmental journey | Spatial progression | A real environment carries the eye from entry point through organizational expansion |

## Selection Rules

1. Write the investor conclusion first.
2. Choose the smallest visual that proves it.
3. Use a flow only for causality or transformation.
4. Use a comparison only when alternatives share comparable dimensions.
5. Use data only when its definition and source are defensible.
6. Keep detail in notes or an appendix when it competes with the takeaway.
7. Prefer real people, physical artifacts, product UI, or environments when they prove the claim more concretely than generic AI imagery.
8. Never invent identities to humanize a slide; use supplied portraits or identity-safe scenes and treatments.
9. Record `visual_evidence` for every slide: type, real-world subject, source status, diagram necessity, and disclosure.
10. Use a diagram without a real-world element only when relationship, sequence, comparison, or data structure is the proof; record that necessity explicitly.
11. Disclose every photorealistic generated human, workplace, or physical scene visibly as AI-generated and non-documentary/non-endorsing.
